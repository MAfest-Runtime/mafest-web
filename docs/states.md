# 검색·기준 확인의 상태별 동작

화면이 요청 결과를 어떻게 나누고 각 상태에서 무엇을 보내는지 한 곳에 정리한다. 정본은 `contract/public-api-v1.openapi.yaml`(공개 계약 1.5.0)이고, 구현은 `src/lib/useSearchRun.ts`(최초 검색)와 `src/lib/useConfirmSubmit.ts`(확인 답변 제출)다.

## 먼저 구분할 두 가지

| 동작             | Idempotency-Key | 본문                           | 누르는 주체 |
| ---------------- | --------------- | ------------------------------ | ----------- |
| 같은 요청 확인   | 처음과 같은 키  | 처음 요청과 같은 본문          | 사용자만    |
| 새 검색으로 시작 | 새 키           | 새 요청(원 질문부터 다시 시작) | 사용자만    |

- "같은 요청 확인"은 서버가 이미 처리했는지 모를 때 같은 요청을 한 번 더 보내 결과를 받는 일이다. 답을 바꿀 수 없고, 성공을 보장하지 않는다.
- "새 검색으로 시작"은 이전 요청과 무관한 새 검색이다. 이전 요청의 결과를 되살리지 않는다.
- 어느 쪽도 화면이 자동으로 보내지 않는다. 스트림이 `done`·`error` 없이 끊겼을 때의 1회 재시도(`src/lib/searchStream.ts`)만 예외이고, 확인 대기·확인 제출에는 적용되지 않는다.

## 상태 표

| 상태             | 어떤 응답인가                                                                                      | 화면                                         | 다음에 보낼 수 있는 것                                                       |
| ---------------- | -------------------------------------------------------------------------------------------------- | -------------------------------------------- | ---------------------------------------------------------------------------- |
| 확인 대기        | `confirmation_required`(SSE는 `done` 없이 정상 종료, JSON은 `kind`로 구분)                         | 기준 확인 질문과 답변 입력. 결과·답변은 없다 | 답 제출(`POST /v1/search/confirm`). 원 질문에 답을 붙여 새로 검색하지 않는다 |
| 처리 중          | 409 `turn_in_progress`(최초 검색·확인 제출 공통)                                                   | "기존 요청을 처리하고 있습니다"              | 대기 후 "같은 요청으로 확인"(같은 키·같은 본문)                              |
| 처리 결과 불명   | 연결 오류, 504, 일반 5xx, 계약 밖 본문                                                             | "처리 결과를 확인하지 못했습니다"            | "같은 요청으로 확인"만. 자동 재전송 없음                                     |
| 확정된 오류 결과 | 계약 검증을 통과한 `outcome: "error"` 응답                                                         | 오류 결과 화면                               | "새 검색으로 시작"(새 키)만                                                  |
| 영구 종료        | 409 `session_conflict`, 409 `turn_indeterminate`, 410 `session_expired`, 501 `confirm_unsupported` | 각각의 종료 안내                             | 새 검색(새 키)만. `confirm_unsupported`는 새 검색 버튼도 두지 않는다         |
| 응답 형식 오류   | 확인 제출 응답이 계약과 다름                                                                       | "답변을 처리하지 못했습니다"                 | 같은 요청 재전송 없음                                                        |

### 처리 중

- HTTP 응답은 `Retry-After`만큼 기다린 뒤 버튼을 연다. 이미 열린 SSE의 `error` 이벤트는 헤더가 없어 고정 2초 동안 버튼을 잠근다.
- 자동으로 다시 보내지 않는다. 사용자가 누르면 같은 키·같은 본문(확인 제출이면 같은 세션·버전·동작·답)을 보낸다.
- 질문을 바꾸면 이전 요청의 늦은 409와 대기 타이머는 새 화면을 바꾸지 못한다.

### 처리 결과 불명

- 서버가 요청을 받았는지, 저장했는지 알 수 없다. 실패로 단정하지 않고 성공도 약속하지 않는다.
- 500이라는 숫자나 문구로 확정 실패를 추측하지 않는다. 모르는 오류 code를 처리 중으로 추측하지도 않는다.

### 계약 검증을 통과한 오류 결과

- 서버가 `outcome: "error"`로 응답한 확정 결과다. 같은 요청을 다시 보내는 길은 없다.
- 오류 결과를 받았다고 해서 서버에 기록이 저장됐다는 뜻은 아니다.

### 만료·충돌·더 진행할 수 없는 요청

- 입력창과 "같은 요청으로 확인"은 사라지고 안내와 새 검색만 남는다(501은 안내만).
- 모든 상태에서 세션 secret과 사용자의 답은 React 상태에만 있고 URL·콘솔·브라우저 저장소에 남기지 않는다. 새로고침하면 확인은 처음부터 다시 시작한다.
